## 我现在怎么看逃逸分析

以前我会把“逃逸了”当成一个负面结论。后来慢慢发现，它其实只是编译器在告诉你对象的生命周期已经超出了当前栈帧。

真正该看的不是“有没有逃逸”，而是：

- 逃逸是不是发生在高频路径
- 这个逃逸是否可以通过 API 设计避免
- 避免之后是否真的带来可感知收益

## 一个够用的命令

```bash
go build -gcflags="-m=2" ./...
```

输出会很多，但高频路径里反复出现的几类信息非常值得多看几次。尤其是把局部变量传到接口、闭包或返回指针的时候。

## 最后留下来的习惯

不要为了追逐“零逃逸”去写奇怪的代码。逃逸分析更像一面镜子，提醒你 API 是否在不知不觉间扩大了对象的生存期。
