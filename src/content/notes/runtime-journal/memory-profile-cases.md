## 先分成哪几类

我现在会先把“内存上涨”粗分成三种画像：

- 峰值上涨后回落
- 缓慢爬升但仍有锯齿
- 只升不降

这三种画像对应的排查起点完全不一样。

## 锯齿并不是坏事

很多人一看到锯齿就紧张，其实这通常说明 GC 还在有效工作。真正该担心的是锯齿的底部越来越高。

## 比曲线更重要的是关系

单看内存图还不够，我更想把它和这些信息放在一起看：

- 流量曲线
- 响应时间
- GC 次数
- 某些对象类型的 alloc 变化

这样能更快判断问题到底是工作集变大，还是对象 churn 变重。
